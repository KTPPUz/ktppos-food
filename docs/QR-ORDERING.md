# สั่งอาหารผ่าน QR ประจำโต๊ะ

ฟีเจอร์สำหรับ Medium / Enterprise ใช้ Backend, บิลโต๊ะ, หน้าครัว, ชำระเงิน และรายงานชุดเดิม ลูกค้าใช้หน้า `/order/:token` โดยไม่ต้องใช้บัญชีพนักงาน

## ทดลองใช้งาน

1. รัน `npm run dev` แล้วเปิด http://localhost:5173
2. เข้าร้าน Medium หรือ Enterprise ด้วยบทบาท Owner, Manager, Cashier, Waiter หรือ HQ Admin (PIN 1234)
3. เลือก **QR สั่งอาหาร** → โต๊ะ → **เปิด QR รับออเดอร์**
4. เลือก IP เครื่องนี้ในช่อง **ที่อยู่เว็บสำหรับมือถือ** ระบบเสนอ IP เครือข่ายของเครื่องให้อัตโนมัติ
5. ให้มือถือเชื่อม Wi-Fi เดียวกัน สแกน QR หรือกด **เปิดหน้าลูกค้า** เพื่อทดลองในอีกแท็บ
6. ลูกค้าเลือกเมนู ตัวเลือก จำนวน หมายเหตุ → ตะกร้า → **ยืนยันส่งเข้าครัว**
7. พนักงานเปิด **หน้าจอครัว** รายการมีป้าย **ลูกค้าสั่งผ่าน QR** และ **รอบ 1 / รอบ 2** อัปเดตทุก 8 วินาที กดรีเฟรชเพื่อดูทันทีได้
8. ลูกค้าสั่งเพิ่มได้จากมือถืออีกเครื่องด้วย QR เดียวกัน อาหารเข้าบิลเดิม แต่แยกรอบครัว อาหารที่เสิร์ฟแล้วไม่กลับเข้าคิว
9. ชำระจากบิลโต๊ะผ่าน POS ตามเดิม หลังปิดบิลครบ QR เดิมจะหยุดรับรายการ ลูกค้ารอบใหม่ต้องเปิด QR ใหม่

รูป QR เป็น QR Code จริง สามารถพิมพ์หรือดาวน์โหลด PNG ได้ ไม่ใช่ไอคอนตกแต่ง รหัสนี้ผูกกับรอบบริการ จึงใช้เป็นป้ายถาวรข้ามรอบลูกค้าไม่ได้

## เครือข่าย

เซิร์ฟเวอร์เริ่มที่ `0.0.0.0:5173` เพื่อให้มือถือในเครือข่ายเดียวกันเข้าถึงได้ Terminal แสดง URL สำหรับมือถือและหน้า QR มีตัวเลือก IP พร้อมใช้งาน `localhost` และ `127.0.0.1` ใช้ได้บนเครื่องที่รันเท่านั้น

```sh
# จำกัดเฉพาะเครื่องสำหรับทดสอบ
HOST=127.0.0.1 npm run dev

# ระบุ URL จริงของร้านในกรณีมี HTTPS reverse proxy อยู่แล้ว
CUSTOMER_BASE_URL=https://order.example.com npm run dev

# เปลี่ยนพอร์ต
PORT=5180 npm run dev
```

`CUSTOMER_BASE_URL` ช่วยเลือก URL ใน QR เท่านั้น ไม่ได้ติดตั้ง HTTPS, DNS, reverse proxy หรือเผยแพร่เว็บให้อัตโนมัติ ตรวจว่ามือถือเปิด URL ของ IP นี้ได้ และไฟร์วอลล์อนุญาตพอร์ตที่ใช้ก่อนพิมพ์ QR

รุ่นนี้ยังใช้ PIN Demo และ JSON repository ตาม README สำหรับการเปิดใช้จริงผ่านอินเทอร์เน็ตต้องเปลี่ยนระบบยืนยันตัวตน/การจัดเก็บก่อน ไม่มีการเชื่อมรับเงินออนไลน์ในหน้าลูกค้า

## วงจรรอบโต๊ะ

- เปิด QR สร้าง `tableSessions` พร้อม token สุ่ม 192 บิต อายุสูงสุด 12 ชั่วโมง ไม่สร้างบิลเปล่าล่วงหน้า
- ถ้าโต๊ะมีบิลเปิดอยู่แล้ว QR จะผูกกับบิลนั้น ถ้ายังไม่มีจะสร้างบิลเมื่อรับรายการแรก
- หลายมือถือใช้ QR เดียวกันได้และเห็นรายการร่วมกันเฉพาะรอบโต๊ะนั้น
- เรียกเปิด QR ซ้ำสำหรับรอบที่ยังเปิดอยู่จะได้ QR เดิม ไม่สร้างหลายรอบซ้อน
- โต๊ะที่เปิด QR แล้วแต่ยังไม่สั่ง แสดง **เปิด QR รอสั่ง** ในผังโต๊ะ
- ปิดรอบ QR เปล่าได้จากหน้าจัดการ QR; ถ้ามีบิลค้างต้องชำระหรือยกเลิกให้ครบก่อน
- หลังแยกบิล จะหยุดรับออเดอร์ใหม่ แต่ลูกค้ายังดูสถานะได้ รอชำระ/ยกเลิกบิลที่แยกทั้งหมดจึงปิดรอบ
- การย้ายโต๊ะหรือรวมบิลทำให้ QR ต้นทางหมดสิทธิ์ ต้องขอ QR ที่โต๊ะปลายทางใหม่ ประวัติ QR ที่ปิดแล้วเป็น snapshot ไม่อ่านรายการเพิ่มในโต๊ะใหม่
- QR หมดอายุหรือปิดรอบแล้วส่งออเดอร์ไม่ได้ ไม่มีการนำ token เก่าไปเปิดรอบลูกค้าคนถัดไป

## การสั่งและครัว

API ลูกค้ารับเฉพาะ `menuId`, จำนวน, modifier และหมายเหตุ โดยอ่าน tenant/branch/table จาก session และคำนวณราคาที่ Backend รวมราคา override ของสาขา ไม่ใช้ราคาหรือ tableId ที่ลูกค้าส่งมา

รับได้สูงสุด 30 บรรทัด, 20 จานต่อบรรทัด, รวม 50 จานต่อคำขอ และ 100 คำขอต่อรอบโต๊ะ สินค้าหมด ตัวเลือกไม่ถูกต้อง หรือกะปิดแล้วจะถูกปฏิเสธก่อนแก้ไขข้อมูล

ทุกการส่งต้องมี `requestId` เซิร์ฟเวอร์เก็บ hash ของรายการและผลรับออเดอร์ไว้ในข้อมูลรอบโต๊ะ ส่งซ้ำด้วยรหัสและข้อมูลเดิมไม่เพิ่มรายการ ส่งรหัสเดิมกับรายการอื่นได้ 409 หน้าเว็บเก็บ pending request ใน sessionStorage เพื่อให้ลองส่งรายการเดิมได้หลังเน็ตหลุด และตรวจ `acceptedRequests` เมื่อกลับมาเชื่อมต่อ

ออเดอร์มี `kitchenBatches` แยกตามรอบสั่ง ทุก batch มี item IDs และสถานะของตัวเอง จึงเพิ่มอาหารได้ระหว่างครัวทำอาหารหรือหลังเสิร์ฟไปแล้ว โดยไม่รีเซ็ตอาหารรอบก่อน สถานะบิลสรุปจากรอบที่ยังรอทำ/กำลังทำ/พร้อมเสิร์ฟ/เสิร์ฟแล้ว

ยอดในตะกร้าเป็นประมาณการเฉพาะรอบใหม่ รวม VAT/service ตามบิล ยังไม่รวมส่วนลดทั้งบิล ยอดชำระจริงดูที่ POS หลังตรวจรายการ ราคาสุดท้ายยืนยันโดย Backend

## API ที่เพิ่ม

| Method | Endpoint | การใช้งาน |
| --- | --- | --- |
| POST | `/api/tables/:id/session` | ต้องมี session พนักงาน + สิทธิ์ tables + Medium+; เปิดหรืออ่าน QR ของรอบโต๊ะ |
| POST | `/api/table-sessions/:id/close` | ปิดรอบเมื่อไม่มีบิลค้าง |
| GET | `/api/guest/:token` | อ่านเมนู ราคา สถานะ และรายการของรอบนั้นโดยไม่ต้อง login |
| POST | `/api/guest/:token/orders` | ส่งรายการและสร้าง kitchen batch เข้าบิลโต๊ะ |
| PATCH | `/api/orders/:id/kitchen-batches/:batchId/status` | พนักงานครัวเปลี่ยน cooking/ready; ฝ่ายหน้าร้านเปลี่ยน served |

ตัวอย่างส่งรายการ:

```json
{
  "requestId": "e35a512b-18fd-40ab-b383-37c129309457",
  "items": [{
    "menuId": "m1",
    "qty": 1,
    "modifiers": [{"group": "protein", "name": "เพิ่มไข่ดาว"}],
    "note": "ไม่ใส่พริก"
  }]
}
```

Public response ไม่คืนบัญชีพนักงาน PIN audit การชำระเงิน หรือ catalog override ของสาขาอื่น Token ลูกค้าใช้กับ API พนักงานไม่ได้ หลังปิดรอบ POST ได้ 410 และ GET แสดงว่ารอบสิ้นสุดแล้ว

`GET /api/state` เพิ่ม `tableSessions` แบบไม่รวม token และ `customerBaseUrls` เฉพาะพนักงาน ต้องขอ QR ผ่าน endpoint ที่ตรวจสิทธิ์ก่อนจึงจะได้ token

## ตรวจสอบ

`npm test` ครอบคลุม tenant/branch/package/role, ราคาจากเซิร์ฟเวอร์, หลายมือถือ, กดซ้ำพร้อมกัน, validation, expiry, ย้ายโต๊ะ, รวม/แยกบิล และปิดรอบเมื่อชำระ

`npm run test:e2e` ถอดรหัสรูป QR ที่แสดงจริงแล้วเปิดหน้าลูกค้า ทดสอบสอง browser contexts, รอบครัว, ปิดบิล และเครือข่ายขาดหลัง Backend รับรายการแล้ว พร้อมตรวจว่าลองส่งใหม่ไม่เพิ่มอาหารซ้ำ
