# KTP Table — Restaurant POS Demo

ต้นแบบใช้งานจริงตาม Restaurant POS System Scope v1.0 วันที่ 24 ตุลาคม 2026 พร้อม UI ภาษาไทย ข้อมูลจำลอง และ REST API ตรวจสิทธิ์ฝั่งเซิร์ฟเวอร์

## เริ่มใช้งาน

ต้องมี Node.js 22+ และ npm ไม่ต้องตั้งค่า MAMP/PHP หรือฐานข้อมูลเพื่อเปิด Demo

```sh
npm install
npm run dev
```

เปิด http://localhost:5173 แล้วเลือกร้านและบทบาทที่หน้าเข้าสู่ระบบ ใช้ PIN **1234** ทุกบัญชี

```sh
npm run build
npm start
```

โหมด build และ development ใช้พอร์ต 5173 เหมือนกัน รันอย่างใดอย่างหนึ่ง ใช้ `PORT=5180 npm run dev` ถ้าพอร์ตถูกใช้แล้ว เซิร์ฟเวอร์รับการเชื่อมต่อจากเครือข่ายร้านเพื่อให้มือถือสแกน QR ได้ ใช้ `HOST=127.0.0.1 npm run dev` หากต้องการจำกัดเฉพาะเครื่องนี้

| แพ็กเกจ | ร้าน | สาขา | ขอบเขต |

| --- | --- |

## ลองขายหนึ่งออเดอร์

1. เข้า Medium / พิมพ์ชนก · Owner ด้วย PIN 1234
2. หน้าขาย เลือกประเภทและโต๊ะว่าง เลือกเมนู ตัวเลือก จำนวน และหมายเหตุ
3. กด **ส่งเข้าครัว** จากนั้นไป **หน้าจอครัว** → เริ่มทำอาหาร → พร้อมเสิร์ฟ → เสิร์ฟเรียบร้อย
4. ไป **จัดการโต๊ะ** เปิดโต๊ะนั้น → เปิดบิล / รับชำระเงิน
5. กด **ชำระเงินจำลอง** เลือกเงินสด/QR/บัตร กดยืนยัน ใบเสร็จจะปรากฏ และโต๊ะกลับเป็นว่าง
6. เปิด **รายงานการขาย** เพื่อดูใบเสร็จ พิมพ์ หรือส่งออก CSV
7. Owner/Manager เปิดใบเสร็จ → คืนเงินจำลอง → ใส่เหตุผล รายงานและ audit จะอัปเดต

ลอง Small โดยข้ามครัว ชำระเงินจากหน้าขายได้เลย ทดลอง Enterprise โดยสลับสาขาด้านบน หรือสร้างคำขอโอนวัตถุดิบใน HQ แล้วกดอนุมัติ

## ลูกค้าสั่งอาหารผ่าน QR

Medium / Enterprise มีหน้า **QR สั่งอาหาร** ให้พนักงานเปิดรอบโต๊ะ สร้าง QR จริง พิมพ์หรือดาวน์โหลด ลูกค้าสแกนจากมือถือใน Wi-Fi เดียวกัน เลือกเมนูและส่งเข้าครัวโดยไม่ต้อง login สั่งเพิ่มเข้าบิลเดิมและแยกรอบครัว ชำระเงินกับแคชเชียร์ตามเดิม QR ปิดเมื่อจบบิลและต้องออกใหม่สำหรับลูกค้ารอบถัดไป

ดู [คู่มือ QR และการเชื่อมต่อมือถือ](docs/QR-ORDERING.md) สำหรับวิธีใช้และ URL เครือข่ายของร้าน

## ข้อมูลและการจัดเก็บ

- 3 tenant / รวม 5 สาขา / 30 เมนู / 6 หมวด พร้อมรูปและตัวเลือก
- 15 โต๊ะ, 20 วัตถุดิบต่อสาขา และ 8 พนักงานต่อ tenant
- ยอดขายย้อนหลัง 30 วัน พร้อมคิวครัวหลายสถานะและตัวอย่างการคืนเงิน
- ชื่อและราคาเมนู ตัวเลือก และสถานะหมด แยกตาม tenant; Enterprise มี branch price override
- ข้อมูลที่แก้ไขบันทึกใน `.data/demo.json` ด้วยการเขียนไฟล์ชั่วคราวแล้ว rename
- ใช้ `DATA_DIR=/absolute/path npm run dev` เพื่อแยกชุดข้อมูล
- กลับข้อมูลตั้งต้น: หยุดเซิร์ฟเวอร์ สำรองไฟล์ถ้าต้องการ แล้วลบเฉพาะ `.data/demo.json` จากนั้นรันใหม่
- session อยู่ในหน่วยความจำและ token อยู่ใน sessionStorage หลัง restart เซิร์ฟเวอร์ให้เข้าสู่ระบบใหม่
- ภาพอาหารเป็นภาพประกอบจาก Unsplash และฟอนต์จาก Google Fonts ต้องมีอินเทอร์เน็ต รูปไม่ได้เป็นภาพอาหารของร้านจริง

## การคำนวณและธุรกรรม

ราคาที่ใช้จริงอ่านจาก catalog ที่ API ไม่รับราคาจาก client ยอดสินค้า = ผลรวม (ราคาฐานตามสาขา + modifier) × จำนวน หักส่วนลดก่อนคำนวณ service และ VAT ปัดทุกขั้นเป็นสองตำแหน่งตามลำดับ

ส่วนลดเป็นจำนวนเงินบาทและต้องได้รับสิทธิ์ Manager ขึ้นไป กำหนดภาษี/บริการได้ 0–30% ใช้ค่าที่ snapshot ตอนสร้างบิล บิลเก่าไม่เปลี่ยนอัตราตามการตั้งค่าใหม่

API ปฏิเสธ payment ครั้งถัดไปเมื่อบิลปิดแล้ว แม้ได้รับคำขอพร้อมกัน แยกบิลแบ่งส่วนลดตามสัดส่วนและเก็บส่วนต่างปัดเศษเพื่อรักษายอดรวมเดิม บิลใหม่จากการแยกไม่มีโต๊ะ สามารถเปิดได้จากรายการบิลเปิด

บิลส่งครัวแล้วเพิ่มรายการได้ โดยรายการใหม่มีหมายเหตุชัดเจนและบิลกลับเข้าคิวเมื่อเคยพร้อมเสิร์ฟ/เสิร์ฟแล้ว การยกเลิกรายการต้องมีผู้ดำเนินการ เวลา เหตุผล และแสดงรายการยกเลิกให้ครัวเห็น รายการสุดท้ายต้องยกเลิกทั้งบิล การคืนเงินจำลองเป็นเต็มบิลและทำได้ครั้งเดียว

Enterprise ตัดวัตถุดิบตามสูตรตัวอย่างเมื่อชำระเงินและคืนให้เมื่อคืนเงิน สต๊อกไม่เพียงพอจะชำระไม่ได้ การโอนยังไม่เปลี่ยนสต๊อกจนอนุมัติ ป้องกันอนุมัติซ้ำ

## ขอบเขตของรุ่นนี้

นี่เป็น interactive mockup ที่มี demo backend ใช้ Express และ JSON repository เพื่อให้เปิดทดลองง่าย ยังไม่ได้ใช้ MySQL, NestJS หรือ WebSocket หน้าครัว poll ทุก 8 วินาที ข้อมูลตัวอย่างไม่ใช่ข้อมูลประกอบภาษี PIN แบบง่ายและ session ในหน่วยความจำมีไว้สำหรับ local demo เท่านั้น

ยังไม่เชื่อมเครื่องพิมพ์ POS, ลิ้นชักเงิน, QR ชำระจริง, payment gateway, delivery platform, e-Tax, บัญชี หรือรับประกัน offline/production หน้าใบเสร็จพิมพ์ผ่าน browser print มี mock receipt แทนเครื่องพิมพ์จริง

ไฟล์ React/CSS และหน้าจอที่รันได้เป็นต้นแบบเทียบเท่า high-fidelity prototype ไม่มีไฟล์ Figma แยก คลังกลางแสดงผ่านการบริหารวัตถุดิบรวมของ HQ และการโอนระหว่างสาขา ยังไม่มี entity คลังกลางแยก, supplier CRUD, ใบสั่งซื้อ, คืนเงินบางส่วน หรือแก้ไขสูตรจาก UI หากต่อ production ต้องย้าย repository ไปฐานข้อมูลแบบ transactional, เพิ่ม password/identity จริง, durable idempotency, realtime, migrations และการทดสอบระดับ deployment

## ส่วนลดรายเมนูอาหาร

ไปที่ **เมนูอาหาร → แก้ไข → ส่วนลดเมนูอาหาร** เลือกไม่มีส่วนลด ลดเป็นเปอร์เซ็นต์ หรือจำนวนเงินบาทต่อจาน แล้วบันทึก หน้าจะแสดงตัวอย่างราคาหลังลด ราคาเดิมและราคาลดจะแสดงทั้ง POS และหน้าลูกค้า QR

ส่วนลดใช้กับราคาพื้นฐานของสาขานั้นทุกจาน ตัวเลือกเสริมคิดเต็มราคา จากนั้นจึงหักส่วนลดทั้งบิล คำนวณ service และ VAT ส่วนลดรายเมนูตั้งร่วมกันทั้งร้าน ไม่แยกส่วนลดแต่ละสาขา แต่คำนวณจากราคาของสาขานั้น ส่วนลดเงินสดสูงกว่าราคาอาหารจะลดได้สูงสุดเท่าราคาอาหาร ราคาจึงไม่ติดลบ

ผู้มีสิทธิ์จัดการเมนูเท่านั้นที่แก้ส่วนลดได้ เปลี่ยนโปรโมชั่นแล้วใช้กับรายการที่เพิ่มใหม่ รายการเดิมและใบเสร็จเดิมคงราคาที่บันทึกไว้ ใบเสร็จแสดงส่วนลดเมนูที่รวมอยู่ในราคาแล้วและไม่หักซ้ำ
